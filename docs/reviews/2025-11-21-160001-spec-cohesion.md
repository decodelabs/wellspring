### Issues

  - docs/meta/spec.md:142-148 claims callable identity is case-insensitive for class and method names. In practice only function/method
    names are lowercased; class names in static/array callables are kept as-is (wellspring/src/Wellspring.php:101-123), so Foo::bar and
    foo::bar produce different IDs. Spec should say class names are case-sensitive (methods are lowercased).
  - docs/meta/spec.md:142-149 states “register always deduplicates” and implies duplicates are ignored globally. Wellspring::register() only
    guards against previously Wellspring-managed loaders (wellspring/src/Wellspring.php:40-47); if a callable was already registered via
    SPL, registering it through Wellspring adds a second entry and it will still execute twice (the queue handler merely skips duplicates
    while checking, it doesn’t unregister them—see wellspring/src/Wellspring/QueueHandler.php:52-111). Spec should narrow the promise to
    “Wellspring-registered callbacks aren’t added twice.”
  - docs/meta/spec.md:178-185 describes $remaps as a remap counter. The implementation increments $remaps on any observed queue change, even
    if no reordering occurred (wellspring/src/Wellspring/QueueHandler.php:119-120). Clarify that it tracks queue changes rather than only
    remaps, or adjust the code.
  - No automated tests exist (wellspring/tests is absent); the testing strategy in docs/meta/spec.md:418-432 is aspirational. Worth adding a
    minimal suite covering priority ordering, duplicate handling, and counter semantics to match the spec.

### Suggestions

  1. Update the spec to reflect the actual identity rules, deduplication scope, and counter semantics.
  2. Optionally tighten code to match the current spec instead (normalize class names in IDs, skip registering callbacks already present in
     SPL, only bump $remaps when a reorder happens).
  3. Add PHPUnit coverage for priority ordering, duplicate handling (SPL vs Wellspring), and the $checks/$remaps counters so future spec
     changes stay aligned.
